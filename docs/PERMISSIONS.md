# Permissions and coverage

| Permission | Consent | Reason |
| --- | --- | --- |
| storage | Required | Session tab/automation state, local bounded audit/history/configuration and enterprise managed settings. Access restricted to trusted contexts. |
| scripting | Required | Run small top-frame runtime/aggregate probes, optional selected-API stack hints and best-effort delegation boundaries; backfill the isolated sensor on accessible sites. |
| webNavigation | Required | Receive same-document navigation events and verify sensor messages against Chrome's current top-frame document ID. No browsing history API or URL persistence. |
| alarms | Required | Refresh evidence and retention after MV3 worker suspension; one-minute interval. |
| http://*/*, https://*/* | Required host permissions | Automatic document-start monitoring across accessible web tabs without any popup/Scan/activeTab prerequisite. Chrome site-access controls and enterprise restrictions still apply. |
| declarativeNetRequestWithHostAccess | Optional API permission | Adds tab-wide quarantine and delegation destination rules on authorized hosts, including matching HTTP(S)/WebSocket handshakes. Existing connections and ungranted hosts remain gaps. |
| debugger | Required at installation | Detection calls getTargets passively. Separately, an explicit user observation lease may attach to a selected tab and enable Network/Page metadata events; no body/cookie/DOM retrieval commands. Chrome can refuse attachment. Own sessions never score as agent evidence. |
| downloads | Optional API permission | Explicitly enabled browser-wide hostname-only observation, or a separately confirmed policy canceling ALL new browser downloads. No sole-agent/tab guessing; cancellation is acknowledged only after Chrome confirms. |
| notifications | Optional API permission | Explicitly enabled hostname-free OS notifications; activation checks a fresh matching tab assessment. In-page alerts do not depend on it. |

These permissions belong to one manifest used by every deployment. Managed settings change behavior, not the build or its permission declarations.

Returning a released tab uses script `history.back()` inside the packaged containment page, requested by an authenticated worker message only after containment cleanup. Chrome retains the prior navigation entry; AgentGuard does not read or store its URL. No `history`, `tabs` or other new permission is needed. An absent history entry or rejected navigation is not reported as a restored page.

`tabs` is intentionally absent: tab IDs and lifecycle operations need no permission; URL properties are visible through effective host access. `activeTab` is absent because monitoring is automatic. No cookies, webRequest, history, management or nativeMessaging. User exports use an in-memory download link without downloads permission. The emergency shortcut uses the manifest `commands` key, not an additional API permission. Optional service requests use existing HTTPS host access; no request occurs merely by installing/opening the UI. They require configured enablement and a manual action; contributions additionally require explicit consent.

Optional DNR permission requests happen directly inside a UI gesture, not after background messaging. Withheld site access is shown as reduced coverage. Required debugger permission does not bypass Chrome or organization restrictions. The extension checks actual passive API access; missing, rejected or timed-out access is unavailable, as is a tab absent from inspectable targets. It reports reduced coverage without assuming the exact cause. Without positive automation evidence, this gap yields UNMONITORED, never human or safe. Chrome internal pages, Chrome Web Store, other extension pages and incognito (manifest disables it) are not monitored.

Sources: [declare permissions](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions), [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs), [optional permissions restrictions](https://developer.chrome.com/docs/extensions/reference/api/permissions).

Observation-specific attach can be refused under Chrome host, screenshot/DLP or other enterprise restrictions. No fallback active probe or forced takeover is attempted. Failure is unavailable observation coverage, not human/safe or successful enforcement. Passive attachment inventory is conservatively unavailable while AgentGuard owns an observation session, preventing self-attribution. Detachment is attempted at lease expiry/navigation; browser scheduling can delay it, and failed cleanup remains visible. See [debugger policy restrictions](https://developer.chrome.com/docs/extensions/reference/api/debugger#enterprise-policy-restrictions), [downloads](https://developer.chrome.com/docs/extensions/reference/api/downloads), [notifications](https://developer.chrome.com/docs/extensions/reference/api/notifications), [commands](https://developer.chrome.com/docs/extensions/reference/api/commands).
