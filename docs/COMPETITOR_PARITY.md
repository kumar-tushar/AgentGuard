# Competitor parity and independent implementation decisions

## Research scope and evidence

Research date: 2026-09-18. Repository: [opena2a-org/ai-browserguard][repo], pinned to commit [`a4ca981c65254b9e95bfbca2411881720a5c9e81`][commit] (2026-08-11). The inspected source manifest is version 0.7.0. The [Chrome Web Store listing][store], extension ID `ojphpdmabflmcjhglfogmkdgchkncikf`, also reports 0.7.0, updated August 4, 2026. The published package was not downloaded, installed, or compared byte-for-byte with this source; source observations are not certification of the store binary.

Method: read the public repository, source, tests, ADRs, field report, and store description. No competitor code was executed, imported, or copied into AgentGuard. No branding or visual assets are reused. References below are immutable source links unless labeled listing. Comments and marketing assertions are not treated as experimental evidence. A test present in their tree means a test was inspected, not that this research independently ran or passed it.

The **Current AgentGuard behavior** column records the starting implementation for this expansion: the single-extension migration, with 129 unit/integration tests and 5 Playwright tests previously reported passing. It is deliberately a gap-analysis baseline, not a claim that planned features below already ship. [CODEX_HANDOFF.md](CODEX_HANDOFF.md) and [CODEX_STATE.json](CODEX_STATE.json) track implementation progress. Existing test references identify baseline coverage; tests prefixed **Planned** are acceptance requirements, not completed tests. Every decision states its rationale and implementation status.

## Research findings that constrain implementation

### Stack visibility is conditional, not a universal CDP tap

The competitor stack module explicitly notes that an extension's own call stack cannot reveal some other CDP execution. The shipped interceptor hooks stack formatting and probes wrapped API calls in a secure-context branch. Its probe can send a raw stack snippet. AgentGuard must instead emit fixed signature IDs only. A source comment claims stack signatures cannot be forged or hidden; this is not accepted as a security property. Names/source labels are page-realm input, and uninstrumented/native actions need not execute a detectable wrapper. [Stack module][stack], [interceptor][interceptor].

Independent validation must show **how** a real framework call reaches the sensor, not merely match a pasted stack string. Track instrumented API surface, absent/tampered hooks, formatter compatibility, performance and teardown. Framework attribution stays heuristic even after a successful fixture; product identity remains separate.

### Debugger presence and environment are not product identity

The debugger module's built-in DevTools heuristic is browser-wide rather than a proof of which debugger controls a particular target. Its URL/title vendor lookup is page-controlled. AgentGuard will not use either as authenticated attribution. A debugger-only observation remains suspected even if no DevTools target is visible. [Debugger source][cdp].

The environment module's vendor classifications can be reached using generic Linux, renderer, plugin or screen traits. Those combinations also describe legitimate desktops/VMs. Their source comments are hypotheses, not independent controller verification. Use environment categories, family caps and measured false-positive controls. [Environment source][environment].

### “Allow once” and downloads require stronger scope

The competitor's notification map stores tab/capability/URL; overrides are separately consumed by page and isolated-world sets. Inspection establishes this implementation, not a demonstrated exploit. AgentGuard's acceptance contract requires a single authoritative consumption, binding to document/session/action, bounded lifetime and revocation. Sending a grant successfully is not evidence that the blocked operation resumed. [Handlers][handlers], [monitor][monitor], [interceptor][interceptor].

Browser download events lack a reliable originating-tab binding in the inspected attribution function. Matching destination/referrer hostname does not establish an actor, and the first-active-agent fallback is explicitly uncertain. The handler nevertheless uses the selected tab's delegation to cancel and records blocked before confirmed cancellation. AgentGuard must not adopt that attribution or success inference. The source correctly omits Allow Once for already-cancelled downloads; retry is distinct from undo. [Attribution][downloads], [handler][download-handler].

### Native input can be observed without being attributable

The competitor's scope helper describes external native input as unobservable in its action timeline. This is a limitation of its attribution/enforcement model, not proof that a Chrome content script cannot receive browser-generated DOM events. AgentGuard can observe permitted aggregate DOM events, but `isTrusted` does not distinguish a person from CDP/native automation. Label these as activity observed during a session, not actions performed by a named agent. [Enforceability source][enforceability], [Chrome debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger), [DOM event trust specification](https://dom.spec.whatwg.org/#dom-event-istrusted).

### Historical reports are not current failures

The repository's [July field report][field-report] records kill-switch recovery, missing attribution and Allow Once usability issues in 0.6.0. The pinned code includes subsequent handling for several of them. This document uses the report to derive regression scenarios, not to claim every historical issue remains in 0.7.0. Likewise, ADR-007's later corrections supersede its initial single-debugger-client and WebSocket assumptions. AgentGuard must validate the installed Chrome version rather than repeat superseded comments. [ADR-007 corrections][network-adr].

## Release evidence still required

This research does not certify AgentGuard feature parity. Before marking a planned row implemented: add runtime code, map acceptance tests, run typecheck/unit/integration/build/E2E gates and record exact results in the handoff. A fixture-only parser test is not real-framework verification. DevTools, real Selenium/Puppeteer, available Codex/Claude integrations, managed Chrome policies and native notification/shortcut permission behavior must be labeled untested where the environment cannot exercise them. No unavailable tool identity may be fabricated to complete the matrix.
