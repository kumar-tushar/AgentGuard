# AgentGuard architecture

## Product contract

AgentGuard reports evidence of browser automation, not proof of AI intent. No available Chrome API identifies an arbitrary external AI controller. `identifiedAgent` is null unless a future authenticated integration supplies independently verified identity. Framework hints are explicitly unverified.

Shared states are `AGENT_ACTIVE`, `AGENT_CONNECTED`, `AUTOMATION_LIKELY`, `AUTOMATION_SUSPECTED`, `NO_AUTOMATION_OBSERVED` and `UNMONITORED`. None asserts human control or safety. Current detectors emit the latter four; the session state machine supports ACTIVE→CONNECTED decay but stronger correlation that emits those states is a later phase. A positive WebDriver flag supports likely automation; ambiguous debugger/fingerprint signals support suspicion. Behavior is activity context only, never positive automation evidence. No automation observed requires available runtime and debugger coverage with no positive signals. Coverage gaps without positive evidence yield UNMONITORED. Confidence is heuristic support, not a calibrated probability.

## Repository design (defined before feature implementation)

```
src/shared/       versioned contracts, validation, domain normalization
src/detection/    common detector interface, independent detectors, scoring, identification
src/content/      bounded MAIN probe, ISOLATED behavior collector, event sensor and tab notice
src/policy/       pure policy evaluation, no Chrome API dependencies
src/enterprise/   validated defaults + managed configuration precedence
src/delegation/   bounded user grants, scopes, expiry and pauses
src/session/      sanitized per-session report summaries
src/integrations/ explicit opt-in bounded HTTPS clients, no backend deployment
src/audit/        bounded local event store and future sink interface
src/background/  Chrome adapters, tab lifecycle, orchestration, trusted message router
src/ui/          React popup, options, blocked-tab UI and shared components
public/          managed-storage schema and extension assets
tests/           unit, service-worker integration and browser extension tests
docs/            implementation plan, acceptance matrix, permissions, operations
```

The core accepts sanitized snapshots; browser calls stay in adapters. Flow: Chrome events/alarms → tab snapshot → detector registry → score and identity → policy decision → enforcement → local audit. Detector errors become coverage gaps, not clean bills of health. No future backend code runs in the extension by default. `AuditSink` and versioned exports define the backend boundary; a deployment must supply authentication, consent, transport, retention and server authorization before connecting it.

## Lifecycles and trust boundaries

Service worker listeners register synchronously. Each worker activation inventories and assesses existing tabs. Static document-start sensors, tab/window events, same-document navigation and the minute alarm trigger bounded reconciliation; the popup reads stored results only. `storage.session` preserves tab/automation-session state through worker suspension but clears on full browser restart. `storage.local` stores configuration, bounded audit and ended-session history. Navigation invalidates previous-document evidence immediately; generation/configuration guards discard late results. Tab observations run four at a time, sharing one sanitized debugger-target snapshot per batch. All inventoried tabs are processed; tab assessment retention is capped at 500 and an explicit capacity warning is shown above that. Evidence expires after at most 90 seconds, bounded by earliest supporting evidence expiry; open UI views expire independently. Restricted pages remain unmonitored. Top-frame probes cannot cover every iframe or cross-origin controller.

Behavior collection runs in an isolated world, installs once per document, keeps bounded aggregates and expires without refresh. It records counts/coarse intervals, never keys, values, coordinates, DOM contents or selectors. The separate event sensor batches bounded counters after configuration acknowledgement and stops activity collection without renewal. Its messages are strictly validated against sender extension ID, top frame, active document ID, timestamp, sequence and rate limits; Chrome's current frame is rechecked before scheduling. `DocumentActivity` consumes accepted document-bound batches once into session counters; stale, replayed and previous-document samples are discarded. Consuming before a failed session write may lose a sample but cannot replay it and inflate counts. Activity remains tab-level observation, not controller attribution or stronger ACTIVE/CONNECTED correlation. MAIN-world results are hostile and rebuilt through allowlist validation. No page-to-extension `postMessage` command channel exists. Only packaged UI pages can mutate settings, export logs, quarantine or close tabs; content sensors cannot.

Scoring uses the maximum within a correlated family, then combines runtime/debugger families with explicit caps. Runtime WebDriver and framework markers share a family. `detection/evidence` accepts automation indicators only from correctly paired WebDriver/fingerprint/runtime or debugger/debugger sources. The behavior detector reports available activity context and optional recent trusted activity, never timing or synthetic-event automation indicators; the engine rejects retired behavioral detector output and the pure scorer ignores legacy/crafted indicators even beside real evidence. WebDriver ≥0.8 or independent debugger support with combined score ≥0.75 yields AUTOMATION_LIKELY. Debugger-only evidence never identifies an agent. No positive evidence has a zero support score, not a probability of human control.

`assessmentDeadline` separates activity-context expiry from control-evidence/assessment expiry in the monitor and UI; expired context is pruned without changing classification, policy or control score. Session observations likewise cap control TTL using automation evidence only. Restored tab records must satisfy the current evidence/scoring contract, so old behavioral-only positives/policies are discarded until fresh monitoring. Session history still parses retired fixed IDs for compatibility, but new positive observations require control evidence and behavior-only active recovery records end as no_evidence. Existing audit/history and quarantine records are not erased or automatically released. The stored/managed behaviorEnabled key remains compatible; its settings label is Activity context, not a detection toggle.

The versioned packaged runtime registry (`src/shared/fingerprints.ts`) supplies fixed existence-only probe arguments, validator IDs, evidence weights/descriptions and framework labels. Provenance/maintainer fields are not observed controller identity. Unverified legacy entries have no claimed verified date or supported-version range. A failed marker check returns null for that detector while preserving an independently readable WebDriver flag. Negative observations require available WebDriver, fingerprint and debugger coverage, including after stored-state restoration. See [runtime registry limitations](docs/RUNTIME_FINGERPRINTS.md).

## Automation sessions

`AgentSessionStore` is separate from tab assessments and audit. It serializes mutations, validates every persisted field against static labels/enums, deduplicates observations, preserves session IDs through worker restart and bounds active sessions (500) and per-session timeline (100). Ended history defaults to 50 records/seven days with local/managed limits. The durable envelope also keeps up to the same count of recent active recovery snapshots (default 50+50, hard maximum 500+500). Missing session storage at a full restart archives those snapshots as browser_restart; they never bind to a reused live tab ID. Zero history disables durable active recovery too. Old recovery records are age-filtered before archival. A session-storage transition journal retains terminal records if a cross-area history write fails; losing that journal during a full restart can only recover the last successful durable write, not a failed end/clear action. UNMONITORED is not negative evidence: prior observations keep their original TTL without renewal but cannot appear as current coverage. Dashboard sessions require a matching fresh tab assessment. History/export/clear APIs are UI-only; clear does not terminate active sessions. Controller identity remains null; framework/transport labels are separate. Accepted document-bound activity counters are observations, never evidence of a specific controller or grounds to promote ACTIVE/CONNECTED.

Reports are derived on demand by `session/reports` from strictly validated retained sessions. Exports contain canonical domains, fixed evidence IDs, aggregate counters and coverage warnings, never page contents or URLs. Observation duration is not exact controller connection duration. Lifetime statistics deduplicate stable session IDs and count confirmed containment outcomes separately; failed storage transactions can leave aggregates incomplete.

## Delegation, pauses, emergency controls and updates

`ControlStore` persists bounded tab grants, site/global pauses and fixed-label logs in browser-session storage. Read-Only, Limited and Full Access have explicit expiry; managed `employeeControlsAllowed` and `maximumGrantMinutes` constrain user choices. Pauses suppress optional delegation boundaries, never detection, sensitive-domain policy or the emergency latch. Separate ISOLATED event gates and MAIN API wrappers cover selected synthetic events/recognizable automation stacks only. These are best effort, not a native-input sandbox. Destination lists stay in the extension, never in page globals.

Product copy uses User/user, including display normalization of older saved quarantine reasons. The existing `employeeControlsAllowed` configuration key is retained for managed-policy and stored-settings compatibility; it is not a user-facing label.

`DelegationEgress` owns a distinct DNR ID range. With optional DNR permission it installs per-tab destination rules whose denials beat allowlists; these affect all traffic, including matching HTTP(S)/WebSocket handshakes, not just agent activity. Expiry uses a dedicated alarm and regular reconciliation. Already-open connections, scheduling and withheld host access remain limitations. Revoking a grant removes its optional boundaries rather than terminating a controller. Allow Once binds a 60-second single-use token to exactly one document/realm/capability and checks current control revision. It does not bypass DNR or sensitive-domain policy. Revocation, navigation and emergency activation invalidate the exception; native input remains outside page hooks. If cleanup cannot run after worker/config transitions, prior hooks self-expire within 90 seconds.

`EmergencyController` persists a latch before acting on fresh detected tabs, revokes grants/pauses and records actual confirmed/failed outcomes. Popup actions require confirmation; Ctrl+Shift+K (Command+Shift+K on Mac) explicitly requests emergency quarantine. Future positive detections are reactively quarantined until reset. Reset does not release quarantines. Saved outcome IDs are historical only after restart, never action targets. External processes and new tabs cannot be universally stopped.

`UpdateController` stages version metadata and defers automatic reload while grants, quarantines or emergency state are active. Explicit application confirms possible interruption. No remote code is fetched by this controller.

## Passive debugger history

`DebuggerIntelligenceStore` consumes the same browser-wide snapshot used by detection; it never calls Chrome, attaches a debugger, or changes scores. It retains at most 1,000 targets and eight fixed-label transitions per target in trusted browser-session storage. Records contain opaque target ID, fixed type, tab ID/canonical domain when available, sampled attachment state and observation times. Tab removal schedules a batched inventory-only refresh; replacement joins the normal observation batch.

Failed inspection marks coverage unavailable without inventing detachment or disappearance. Duplicate/older captures cannot renew evidence. Failed persistence does not block newer live observations; the latest complete snapshot is retried on subsequent captures. Restored records are strictly validated. Current attachment views expire after 90 seconds; retained history does not imply current control. Settings → Coverage & permissions shows at most 50 retained records with an explicit count. Sample spans are not exact connection durations, and controller ownership remains unknown.

## Toolbar and in-page alerts

`updateBadge` selects the packaged red Orbit Pointer icon for positive automation states and policy warnings/containment; negative or unmonitored assessments restore the green icon. Every update explicitly clears badge text, including legacy overlays; no state adds text or symbols over the icon. Tooltips retain qualified states and never imply verified identity or safety. The single Vite build generates matching 16/32/48/128-pixel PNGs from code-native open-orbit and inset-cursor outlines, with rounded corners, subtle green/red shading, transparent cutouts and four-by-four supersampling. Both palettes share identical geometry/alpha, occupy nearly the full canvas, and need no image dependency. Chrome controls the actual toolbar slot size.

The shared React `Brand` component reuses the packaged 128-pixel logo in popup, settings and containment headers and synchronizes each document's 32-pixel favicon. Vite inserts a local favicon link into every extension HTML page after HTML transformation. Popup color follows its fresh active-tab assessment, policy warnings and quarantine record; the containment page uses red only for a confirmed record and returns to green on release. Settings branding remains neutral. No page-facing asset exposure or new permissions are required.

`ui/styles.css` defines the shared dark-surface, text, mint-accent, amber-uncertainty and red-risk tokens and a four-pixel spacing scale. Popup hierarchy puts the current assessment and tab actions before supporting evidence and browser totals; the main answer is not duplicated in a status chip. Settings use a shared sidebar, card/form/table rhythm and local-scroll table wrappers; narrow screens switch navigation to a horizontal rail and stack forms. `ui/icons.tsx` supplies decorative, typed inline SVGs without changing accessible control names or packaged Orbit Pointer assets. Visible focus, dark native controls, reduced-motion preferences and contrast are checked in real Chromium. In-page alerts keep their self-contained closed-shadow styles aligned with the same palette, without changing activation, expiry, privacy or mute behavior.

The popup document alone has an explicit 400-pixel width/minimum width, and its shell fills that width. It must not use a viewport-based maximum: Chrome's content-driven native popup sizing can otherwise feed a narrow initial viewport back into layout. Chrome caps the native height while the document scrolls vertically; settings and containment do not inherit this width. A separate regression opens the actual action popup with `chrome.action.openPopup()` on first open and reopen, inspects its native CDP target without viewport emulation, and verifies width, height, header alignment and vertical scrolling. Ordinary tab-rendering tests remain useful but cannot establish native popup sizing.

`TabAlerts` is a presentation-only service, separate from scoring, policy and audit. After observation batches and tab lifecycle events, the worker reconciles fresh positive sources into a scroll-bounded vertical stack on each window's active accessible HTTP(S) tab. It targets the current top-frame document ID and injects self-contained `renderTabAlert` in the ISOLATED world. One frame lookup per source is shared across recipients with concurrency four. Up to 500 sources and 500 active-window hosts are retained; no broadcast to every background tab. Cards display canonical source domains only inside closed shadow content, never in page-readable host attributes. No page titles or URLs are included. Revisioned snapshots reject older deliveries, deduplicate by source tab, preserve keyboard focus and expire cards independently with their evidence. Negative/unmonitored results, disabled monitoring, source navigation and closure remove cards. Pinning and an open extension UI are not prerequisites.

A trusted click or Enter/Space sends an exact `ACTIVATE_TAB_ALERT` packet containing only its schema version and issued token. No visible dismissal hint is shown. The worker derives the host tab/document from Chrome and resolves its issued token to a fresh source assessment/document; callers cannot choose a destination ID or URL. It rechecks both documents, activates the existing source tab and focuses its window, then persists that source's 24-hour mute before acknowledging. Failed activation/focus/save never claims a successful mute; a tab switch already performed cannot be rolled back reliably if saving fails. `agentguard.alert-mutes.v1` holds at most 1,000 source tab IDs/deadlines in trusted `storage.session`; tokens are memory-only. Serialized updates preserve simultaneous preferences. Mutes suppress that source on every host and survive navigation/worker suspension; close/replacement deletes them, full browser restart clears them, and expired/closed records are filtered on load. Local acknowledged source mutes suppress queued renderer snapshots. Unavailable preference reads suppress notices until reconciliation can reload them. Detection, audits and policy enforcement remain independent.

No new permissions are needed. Chrome restrictions and withheld site access can prevent injection. Closed shadow content is not a trusted browser UI boundary: a hostile page can obscure/remove/spoof the host, and automation can generate trusted clicks. The notice is an awareness aid, not tamper-proof security UI or proof of human acknowledgement.

## Policy and containment

Policies match canonical hostnames on label boundaries, not URL substrings. Mode `monitor` records; `warn` produces a warning decision/red icon; `block` quarantines a matching sensitive tab once the configured risk threshold is met. This is reactive protection: a page may have acted before detection. No policy claims to be a complete DLP boundary.

Quarantine navigates the tab to a packaged extension page, destroying its current document. When the optional DNR-with-host-access permission and persistent host access are granted, a session rule also blocks HTTP(S) requests in that tab for authorized hosts. The rule explicitly enumerates resource types including `main_frame`; Chrome's default omits top-level navigation. Release removes the rule and persists the cleared record before requesting return navigation under the same per-tab lock. Cleanup-only release on tab closure never navigates. Closing a tab is a separate explicit emergency action. These operations cannot terminate an external agent, detach someone else's debugger, stop browser/OS automation, undo prior requests or prevent new tabs. Quarantines and their session rules are reconciled after worker restart and tab closure; reconciliation failure surfaces a health error without disabling recovery commands. A quarantine record is distinct from the currently loaded document: navigation away triggers reactive restoration, and the monitor observes escaped pages until replacement succeeds. Restoration cannot guarantee that the destination has not already acted. Enforcement failure is visible and audited.

`returnToPreviousPage` checks that the current completed tab is still the packaged containment page. The Chrome adapter sends a private top-frame command containing only a tab ID and random nonce. The containment-page listener accepts only AgentGuard's own background-worker sender and exact command fields, then calls script `history.back()` for one entry. This avoids toolbar-style Back skipping pages without prior user interaction. The Navigation API's same-origin-only `canGoBack` cannot test for the preceding web page; only the history length is checked, without reading entries or URLs. The response distinguishes requested/not-needed/unavailable; a request is not a guarantee of completed loading or preserved form state. Missing history/API failures are shown with retry guidance, including pages released before this change. Already-returned/unrelated tabs are not navigated. Detection and policy continue and may quarantine again. No history permission, original-URL persistence or policy bypass is introduced. See the [Chromium history intervention](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/history_manipulation_intervention.md) and [Navigation API origin limits](https://html.spec.whatwg.org/dev/nav-history-apis.html).

## Single build and permissions

One source tree and one manifest produce one `dist/` extension for individual and enterprise-managed users. Required APIs: `storage`, `scripting`, `alarms`, `debugger`, `webNavigation`; required hosts: HTTP(S). Optional APIs are `declarativeNetRequestWithHostAccess`, `downloads`, `notifications`. There is no activeTab or manual-scan prerequisite. Chrome forbids optional debugger permission. Managed configuration changes behavior, not artifacts. No `tabs`, `cookies`, `webRequest`, `history`, `management`, remote code or automatic upload is added. See [permissions](docs/PERMISSIONS.md).

Debugger capability reflects successful passive target inspection, not just a declared permission. Missing, rejected or timed-out access and uninspectable tabs have unavailable coverage. Chrome or organization policy may be responsible; a generic failure cannot establish the exact cause. Detectors continue independently. Without positive evidence, a debugger coverage gap yields UNMONITORED. Detection never actively attaches. An explicit, separate observation mode may enable Network/Page CDP events; while AgentGuard owns an attachment, passive inventory is conservatively unavailable rather than self-scored.

## Optional observations and services

`TrafficObserver` caps explicit observation leases at 20 (15-minute collection TTL), keeps 500 memory-only hostname/method/status/time records, discards all other CDP fields without inspecting bodies/headers and never attributes initiators. A serialized browser-session journal records at most 20 owned tab IDs before attach. Worker recovery attempts detach, never silently reattaches; uncertain cleanup remains unavailable coverage. Ownership epochs invalidate in-flight/cached passive captures across attach/detach races. Navigation/closure/config denial ends leases; detach failure is visible and browser scheduling may delay cleanup. Subtargets/workers, prior traffic and unavailable attach remain gaps. `DownloadMonitor` keeps 200 memory-only hostname/outcome records with null tab/controller. It never uses sole-agent or URL-matching attribution. Only an explicit `block_all` policy cancels browser-wide new downloads, and Chrome callback success is required. Permission absence does not imply enforcement.

`DesktopAlerts` is optional and independent of in-page alerts. Generic OS notices contain no hostname, suppress repeat tab notices for ten minutes in the current worker, and activate only a fresh matching source assessment. Worker restart loses in-memory activation bindings; stale notices cannot choose a recycled tab. These are awareness aids, not guaranteed delivery or proof of acknowledgement.

Optional selected-API stack wrappers match only fixed Playwright/Puppeteer source patterns, discard complete stacks immediately and expire without renewal. They share the runtime fingerprint family and never infer a specific AI vendor. A benign function named callFunction is insufficient. Puppeteer remains synthetically tested, not a real-tool version guarantee.

`RemoteServices` has no automatic schedule or startup calls. Explicit packaged-UI operations use saved enablement, approved HTTPS endpoints, credential/referrer omission, redirect rejection, a five-second timeout and a streaming 16 KiB cap. Lookup cache keys contain fixed framework labels; returned names/extra data are discarded and scores never affect detection/policy. Site-declaration cache holds at most 100 HTTPS origins and fixed boolean claims in memory, for 24 hours; no page body or linked attestation is fetched. Contribution payloads contain bounded aggregate counts only and require a positive JSON receipt. No backend, enrollment or authentication is invented. See [contracts](docs/INTEGRATIONS.md).

Without `tabs`, Chrome may omit even an extension document's tab URL. The browser adapter uses `runtime.getContexts` to recognize its own packaged pages; it does not broaden access to other sites. Chrome tab IDs use the full nonnegative signed-32-bit range. DNR rule IDs are allocated separately under a serialized writer, avoiding arithmetic overflow and concurrent collisions.

## Delivery and quality

Strict TypeScript, unit tests, mocked Chrome integration tests and real Chromium unpacked-extension tests. Vite builds HTML/worker into `dist/` and serializes the self-contained sensor into a packaged classic script; packaging creates one ZIP. CSP permits packaged scripts only. Managed schema and runtime validation jointly protect configuration. Tests load the production extension and a disposable optional-DNR-pregranted fixture with unchanged executables, never a distributed edition. Native consent remains a manual check. Node 24.18 is pinned. See [implementation plan](docs/IMPLEMENTATION_PLAN.md), [acceptance matrix](docs/ACCEPTANCE.md), and [enterprise operations](docs/ENTERPRISE.md).
